## Downstream observability

The 2026-08-12 Pi Hub incident left one unanswered `ctx_batch_execute` request
with no way to tell whether the stdio transport decoded it or the registered
handler began. The follow-up adds opt-in request lifecycle records:

- `received`: decoded `tools/call` reached the MCP transport;
- `handler_start`: the registered `ctx_*` callback began;
- `handler_end`: callback returned successfully;
- `handler_error`: callback threw or observed cancellation.

Records go only to stderr when `CONTEXT_MODE_REQUEST_LOG=1`. They contain a
sanitized tool name, opaque process-local correlation id, terminal duration,
and coarse outcome. They exclude arguments, commands, queries, paths, content,
results, raw request ids, auth data, and exception details.

## Pi cancellation boundary

The selective #1029 port forwards Pi's optional tool `AbortSignal` through the
Pi MCP bridge, emits `notifications/cancelled`, rejects the local pending call,
and removes its pending entry. The installed Pi Agent Core 0.84.0 contract
passes `signal?: AbortSignal` as the third registered-tool callback argument.

This is defense in depth. It would not necessarily recover the documented
incident because Pi's abort command itself was blocked and the unanswered MCP
request apparently never entered command dispatch. Pi still needs an MCP
request deadline, EOF-as-failure handling, and run-loop-independent recovery.
