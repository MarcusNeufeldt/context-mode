## Imported upstream fix

### #1056 — shared SQLite close and mmap safety

Cherry-picked as `beea644`.

- Removed close-time `wal_checkpoint(TRUNCATE)` from `closeDB()` so one process cannot mutate the shared WAL/wal-index while sibling processes hold live connections.
- Made `mmap_size` opt-in through `CONTEXT_MODE_MMAP_SIZE`; default is off. This avoids Windows truncate conflicts and uncatchable mapped-file faults when another process replaces or truncates a DB.
- Preserved the already-imported #988 PASSIVE checkpoint timer for hard-exit WAL bounding.
- Preserved the already-imported #1030 transient IOERR retry as a complementary resilience layer.

## Downstream stability fixes

### Session-specific Pi workspace and bridge

A live Pi Hub probe showed the MCP child running from `F:\explore\pi-hub` with no `PI_WORKSPACE_DIR`, `PI_PROJECT_DIR`, `PWD`, or `CONTEXT_MODE_PROJECT_DIR`, even while the Pi session worked in another repository. This caused file sandbox rejection, cross-project data attribution, and unnecessary contention on the `pi-hub` database.

The Pi extension now:

- binds project/session state from `ctx.cwd` / `systemPromptOptions.cwd` instead of extension-load process cwd;
- gives each extension registration closure-local session, pending-context, DB, and bridge state;
- opens one SessionDB handle per registration and closes it on `session_shutdown`;
- spawns `server.bundle.mjs` with both `cwd` and `CONTEXT_MODE_PROJECT_DIR` / `PI_WORKSPACE_DIR` set to the session workspace;
- restarts its bridge if the bound workspace changes, while treating Windows case variants as the same path;
- ensures session metadata exists again after a mid-session workspace rebind;
- detaches a retiring bridge before shutdown waits so a reused registration cannot kill the next session's bridge;
- resolves a detected bare `bun`/`node` runtime to an executable path before spawning from another cwd;
- ignores poisoned literal environment values `"undefined"` and `"null"`.

### Non-destructive content DB lifecycle

Removed automatic content DB file deletion from server startup. SQLite main DB and WAL mtimes do not prove that another process is dead; the prior one-hour WAL heuristic could unlink an active-but-idle DB (#1024). Explicit `ctx_purge` and `ctx_forget` remain the cleanup boundary. Indexed-source retention inside an open ContentStore remains unchanged.
